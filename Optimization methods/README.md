## Установка и запуск

Нужен Python 3.12. Версия фактического расчёта 3.12.14. Команды выполнять из папки репозитория. macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python main.py --generate
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-lock.txt
python main.py --generate
```

Основная команда пересоздаёт синтетические данные варианта, решает модели, выполняет независимые проверки, запускает парный MILP-бенчмарк по три раза, строит графики, обновляет Markdown и report.pdf. Пример без перегенерации входных JSON: `python main.py`. Отдельный контроль сохранённых планов без импорта решателя:

```bash
python check_results.py
```

Не указывать `--generate` после ручного редактирования входных JSON, если их нужно сохранить. Файлы data/ служат входом; results/ и reports/ - воспроизводимые результаты. Повторный запуск обновляет результаты и логи. По умолчанию время каждой MILP ограничено 30 секундами; на исходном компьютере все экземпляры решены до доказанного оптимума. При другом оборудовании time limit не означает оптимальность: проверяйте статус и mip_gap. Встроенные утверждения прервут основной расчёт, если обязательный сценарий или проверка не выполнены.

## Интерпретация статусов и допусков

Optimal - оптимум доказан в рамках численных допусков; Infeasible - совместимого плана нет; Unbounded - неограниченное улучшение; Time limit - остановка до доказательства. Сохраняются только допустимые планы, и наличие вектора само по себе не трактуется как оптимальность. В фактическом расчёте infeasible возникает в ЛР 2 при росте спроса; объяснение конфликта и минимальное неудовлетворение спроса приложены. Для остальных обязательных сценариев получен Optimal.

Проверка ограничений и пересчёта цели использует абсолютный допуск 1e-7. HiGHS получает primal/dual/mip feasibility 1e-9, threads=1, random_seed=10107, presolve=on; LP - dual simplex; MILP - branch-and-cut, целевой mip_rel_gap=0. Время измеряет `h.run()`; построение и проверка в него не входят. Повторяемость времён и побитовое совпадение альтернативных оптимальных планов между платформами не обещаются.

Интегральный зазор: `100*(Z_MILP-Z_LP)/abs(Z_MILP)` для минимума. Финальный `mip_gap` решателя сравнивает incumbent с текущей доказанной нижней границей и отличается от интегрального зазора исходной LP-релаксации.
