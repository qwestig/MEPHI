# Лабораторная работа № 2 — маршрутизация сбора отходов

Вариант 13, как в лабораторной № 1. Задача: обслужить 20 площадок четырьмя машинами вместимостью 35 контейнеров, минимизируя суммарную длину маршрутов с возвратом в депо. Используются собственный генетический алгоритм, OX-кроссовер и перестановка с разделителями.

## Готовые материалы

- `report.md` — отчёт с постановкой, формулами, блок-схемой, примерами и выводами;
- `data/waste_collection.json` — синтетические входные данные, seed 132026;
- `configs/experiment.json` — все параметры серии;
- `results/runs.csv` — 100 запусков: 20 на каждую из четырёх конфигураций ГА и на случайный допустимый поиск;
- `results/summary.csv`, `trajectories.csv` — статистика и сходимость;
- `results/best_solutions.json` — маршруты, загрузки и seed лучших решений;
- `results/constraint_examples.json` — два допустимых и два недопустимых решения;
- `results/experiment_snapshot.json` — конфигурация и данные фактического запуска;
- `results/*.svg`, `results/*.png` — сходимость, распределения, допустимость, карта маршрутов, блок-схема.

## Запуск

Нужен Python 3.10+. Расчёт использует только стандартную библиотеку. Команды ниже выполняются **из корня проекта**, где лежат папки `lab1` и `lab2`:

```bash
python3 lab2/src/run_experiments.py
python3 lab2/src/build_report.py
```

Пути по умолчанию определяются относительно файлов программы, поэтому скрипты можно вызывать и из папки `lab2`. Результаты при повторном запуске перезаписываются. Время работы зависит от компьютера; в приложенной серии оно сохранено отдельно для каждого запуска.

Для **перестроения графиков** требуется Matplotlib:

```bash
python3 -m venv lab2/.venv
lab2/.venv/bin/python -m pip install -r lab2/requirements.txt
lab2/.venv/bin/python lab2/src/plot_results.py
```

Если используете уже имеющееся окружение первой лабораторной с Matplotlib:

```bash
lab1/.venv/bin/python lab2/src/plot_results.py
```

Готовые графики приложены, установка библиотеки нужна только для их повторной генерации.

## Воспроизводимость и конфигурация

```bash
python3 lab2/src/generate_instance.py --seed 132026
python3 lab2/src/run_experiments.py --config lab2/configs/experiment.json --output lab2/results
python3 lab2/src/build_report.py --results lab2/results --output lab2/report.md
lab1/.venv/bin/python lab2/src/plot_results.py --results lab2/results
```

В конфигурации путь `instance` разрешается относительно родительской папки каталога конфигурации (`lab2` для стандартного пути). Для нового экземпляра используйте генератор и задайте его seed. В стандартном отчёте описан приложенный экземпляр и фиксированные параметры; при изменении постановки нужно обновить соответствующий текст отчёта.

Сравниваются все четыре комбинации «штраф/ремонт × обмен/инверсия» при общих seed 20261019–20261038. Бюджет каждого запуска — ровно 10 000 полных оценок, включая начальную популяцию. Элитные особи повторно не оцениваются. Все методы начинают с одной и той же жадной эвристики; случайный поиск делает ещё 9999 случайных проб с ремонтом. Длительность ремонта не включается в число оценок, но входит в измеренное время.

## Модули

- `problem.py` — модель, валидация, кодирование, длина, жадная эвристика и ремонт;
- `optimizer.py` — селекция, OX, мутации, ГА и случайный поиск;
- `generate_instance.py` — генератор данных;
- `run_experiments.py` — независимые запуски, статистика и проверка маршрутов;
- `plot_results.py` — графики по сохранённым результатам;
- `build_report.py` — отчёт и примеры нарушений;

Лучший найденный план имеет длину около 508,13 км; это приближённое решение, доказательства глобальной оптимальности нет.
